# AI-Based Personalised Fitness Activity Planner

A non-clinical activity planning prototype for an academic AI/ML project. It combines a knowledge base, rule-based activity ranking, free-interval search, a personal assistant agent model, and optional grounded LLM explanations.

## Features
- Personal goals, activity preference, daily time budget, planning window and busy blocks
- Schedule search that avoids busy intervals
- Rule-based ranking from a JSON activity knowledge base
- Agent workflow: Observe → Plan → Validate → Explain → Adapt
- Validation for time budget, overlap and chronological order
- AI paradigm comparison in the dashboard
- Optional LLM explanation with grounded evidence and deterministic fallback
- Unit tests

## Run locally
Python 3.10+ recommended.

```bash
python -m venv .venv
source .venv/bin/activate        # macOS/Linux
# .venv\\Scripts\\activate       # Windows
pip install -r requirements.txt
streamlit run app.py
```

## Optional LLM setup
The app works without an API key. To enable the optional OpenAI explanation layer, install the SDK and set environment variables:

```bash
pip install openai
export OPENAI_API_KEY="your_api_key"
export OPENAI_MODEL="gpt-4.1-mini"
streamlit run app.py
```

PowerShell:
```powershell
$env:OPENAI_API_KEY="your_api_key"
$env:OPENAI_MODEL="gpt-4.1-mini"
streamlit run app.py
```

The LLM is only used to explain the already validated schedule. It is not allowed to select or alter schedule slots. The app passes user preferences, validated plan details, and the activity-library facts as grounding evidence.

## Run tests
```bash
python -m unittest discover -s tests -v
```

## Project architecture
1. `app.py` — Streamlit interface and user interaction
2. `planner.py` — activity knowledge loading, interval computation, rule ranking, planning, validation and agent
3. `llm_grounding.py` — optional grounded LLM explanation and fallback
4. `knowledge_base.json` — activity facts and domain rules
5. `tests/test_planner.py` — basic planner tests

## AI paradigms
- Rule-based AI: explicit planning constraints
- Search/optimisation: find activities in available windows
- Machine learning: proposed extension for learning preference weights from feedback
- LLM/RAG: explain plans using retrieved activity facts
- Hybrid AI: combine deterministic planning and grounded natural-language interaction

## Current prototype limitations
- Busy periods are manually entered; no calendar connector is implemented.
- Search uses a greedy interval approach rather than a global optimiser.
- Preference learning is not trained in this version.
- Activity library is illustrative, not a clinical or exercise-science database.
- The optional OpenAI API requires user-provided credentials and network access.

## Non-clinical notice
This application is for general activity planning only. It does not provide medical advice, diagnosis, or treatment. Users should choose activities appropriate to their circumstances and stop if they experience pain, dizziness, or unusual discomfort.


## Responsive chatbot update
A mobile-responsive dark UI and Fitness Coach tab provide recommended questions, chat history, OpenAI responses when `OPENAI_API_KEY` is configured, and FAQ fallback otherwise. Run tests with `python -m unittest discover -s tests -v`.


## Daily Flow timeline UI
The Planner tab renders generated activities as responsive dark timeline cards with start/end times, duration, rationale, and completion checkboxes, matching the supplied Daily Schedule reference. This displays the scheduled workout activities generated by the planner; it is not a full meals/sleep/work calendar.
